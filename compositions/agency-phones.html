An agency phone is a dialing or messaging number
that we own.
There is only one record right now, and at
first glance that does not look like a very
important object.
It is actually one of the most consequential in
the whole library, Because that single row is the
thing that decides whether every call we place and
every text we send is allowed to happen at
all.
Get it wrong, and the carrier or the regulator
takes the number away, and suddenly the entire outbound
engine, the calls and the messages and the leads
and the conversations, all of it stops.
The fields are mostly regulatory housekeeping, and that is
the point.
There is the phone number itself, and the country
code, so the system knows which country's rules apply.
There is the number type, so it is clear
whether this is a local number, a mobile, or
a toll free line.
Then the state field, which is simply the current
status of the number.
And then the three registration identifiers, which are the
real payload.
There is a 10 DLC campaign ID, which is
The United States registration for business texting.
There is a toll free verification ID, which is
the separate check toll free numbers have to pass
before they can send.
And there is a messaging profile ID, which is
the Telmix profile.
The number sends through.
Why is compliance stored in the CRM at all,
rather than just in somebody's head?
Because compliance is not a preference.
It is a hard constraint imposed by carriers and
regulators who are not interested in our pipeline.
If a number is not registered properly, text messages
to it get silently dropped.
If complaint rates go too high on a campaign,
the messaging profile is suspended.
If we try to send from a number that
has not passed toll free verification, nothing arrives and
no error is shown.
So this object is our single source of truth
for whether our outbound is actually permitted.
One row enormous blast radius: Where does it get
used in practice?
At the moment of sending, before anything goes out,
the messaging system reads this record, checks the profile
is active, checks the registration is valid, and only
then releases the message.
That is the whole point of putting it in
the database it turns a legal constraint into an
automated precondition.
When something is not working and texts are mysteriously
not landing, this is the first record you open.
And if you ever want to add a second
number, a new city, or a different channel, you
duplicate this row, get it registered properly first, and
only then start sending.
Never the other way round.
