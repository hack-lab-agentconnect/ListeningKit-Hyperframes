An agency career is a job advert we have
published on the Careers section of the website.
There is one live at the moment.
The reason this object exists separately is worth explaining,
because on the surface a job advert looks nothing
like a marketing page.
But structurally, it is identical.
It has a slug, a canonical path, a search
title, a family it belongs to, and a status.
It is a page, and pages are what the
agency content object renders.
The fields make it clear that that this is
a managed page rather than a PDF somebody uploaded.
The name is the internal identity of the advert.
The title is the actual job title candidates see.
The slug and the canonical path are its address
on the site, and fixing them matters because if
the address changes after the advert has been advertised
on job boards and social media, we lose the
applicants.
The status controls whether it is live or closed.
The family field groups careers pages together, so the
whole careers section can be reasoned about as a
section.
And the primary href is where the Apply button
goes.
Pages?
Two reasons: The first is that a sales page
that is broken loses a lead.
But a hiring page that is broken loses every
applicant you have, because they are applying to a
company and the first impression is the career site.
The second is measurement.
We already track SEO and analytics on marketing pages,
so we can tell which advert brings inquiries.
Doing nothing different for careers means we have no
idea which adverts actually attract people and which ones
waste the spend.
Having them as proper records fixes that.
So where does a person use this object?
When we decide to hire for a role, this
is the record that gets written and published.
When we advertise that role on job boards and
social channels, every link we post points at the
canonical path held here, so we know which adverts
people actually clicked.
And when the role is filled, the status is
updated and the page is retired with a link
to anything that replaced it.
There is one advert live, which usually means there
is one role we genuinely need filling.
The applicants who come in through it land in
the agency career application object.
It surprises people that a job advert gets its
own object here, so let me justify it.
A careers page is a page.
It has an address.
It gets crawled.
It competes for the same attention as every marketing
page on the site, and it has an advert
on it that people actually read, which means it
can be as badly written as any other page,
and nobody would notice because there is no meeting
about the careers page.
Putting it in this database means it gets the
same treatment as a service page.
It gets an owner.
It gets a canonical path, so we know which
advert is the real one when three exist.
It gets a status, so a filled role can
be retired instead of quietly ranking for a job
that is closed.
And it gets a family, so a new city
or a new role is added by copying a
pattern rather than by inventing one from scratch.
